# 内存马专项

## 1. 知识点讲解

内存马 = 不落盘的 webshell：寄生在中间件/框架的运行内存里，以「合法组件」身份处理请求。动因是查杀进化——D 盾、河马、EDR 对落盘马的静态+沙箱检测已非常成熟，红队被迫无文件化。

生命周期三阶段：

```text
注入（RCE/反序列化/JNDI/SSTI/上传一次性孵化）
  → 动态注册组件（Filter/Servlet/Listener/Controller/Module…）
  → 存活至进程重启
```

核心认知：
- **重启即失**是天然短板——内存马只负责「在线通道」，持久化交给 07 分册手法，双通道互补。
- 内存马本体无文件，但**注入载荷**仍要过流量与进程监控一关——注入一次成功即可，载荷可以是一次性的。
- 蓝队查内存马靠「组件与文件对账」（内存里注册了磁盘上没有的类），红队反制靠「类名拟态 + 寄生字节码」。

## 2. Java 内存马核心原理（Tomcat 为主线）

### 组件树（必须背下来的结构）

```text
StandardEngine > StandardHost > StandardContext（= 一个 Web 应用）
  ├─ FilterDef/FilterMap  → FilterChain（doFilter 最先过请求）
  ├─ Wrapper（= Servlet 实例）
  ├─ Listener（ServletRequestListener 等）
  └─ Pipeline-Valve（Tomcat 管道，独立于应用，全局生效）
```

### 注入三步骤（所有形态通用）

1. **拿 StandardContext 引用**（三条路任选）：
   ```java
   // ① 线程上下文类加载器
   WebappClassLoaderBase cl = (WebappClassLoaderBase) Thread.currentThread().getContextClassLoader();
   StandardContext ctx = (StandardContext) cl.getResources().getContext();
   // ② 从 request 反射：request.getSession().getServletContext() → ApplicationContext → context
   // ③ MBean Registry 枚举
   ```
2. **定义组件**：Filter 实现类（defineClass 加载，doFilter 里写触发逻辑）。
3. **注册**：`ctx.addFilterDef(filterDef); ctx.addFilterMap(filterMap);` 并反射调用 `filterStart()` 让它立即生效。

### 各形态对比

| 形态 | 执行点 | 特点 | 查杀难度 |
| --- | --- | --- | --- |
| Filter | doFilter（请求链最前） | 最常用，覆盖全部路径 | 低（工具成熟） |
| Servlet | service | 绑定特定路径，较隐蔽 | 低-中 |
| Listener | requestInitialized | 无路径特征 | 中 |
| Valve | invoke（管道层） | 全局、跨应用 | 中 |
| Spring Controller | registerMapping | Spring 应用专用 | 中 |
| Spring Interceptor | preHandle | 混入已有拦截器链 | 中-高 |
| WebSocket | onMessage | 长连接、流量特征弱 | 高 |
| **Agent（Instrumentation）** | 改已有类字节码 | 复用正常类名，最难查 | **最高** |

Agent 型要点：`VirtualMachine.attach(pid)` → `Instrumentation.retransformClasses()` 把 `javax.servlet.http.HttpServlet#service` 之类已有方法的实现换掉——对账查不出「多出来的组件」，需要 JDK 环境（jre 无 attach）与足够权限。

## 3. 注入通道（按打点场景选）

| 通道 | 说明 |
| --- | --- |
| 反序列化 | ysoserial 触发自定义 defineClass 直接注册（利用链内嵌内存马字节码） |
| JNDI 注入 | Log4Shell / fastjson → 加载字节码注册（配 ldap 服务端返回序列化对象） |
| SSTI / EL 注入 | 表达式执行注册逻辑（02-01） |
| 文件上传一次性孵化 | 传一个「运行即注册内存马并自删」的 jsp——文件马只活几秒，内存马接管 |
| 直接 RCE | base64 class → defineClass → 注册 |

## 4. 武器化

- **冰蝎 Filter 内存马**：AES 加密流量，过常规流量审计；连接特征：特定 Accept/Cookie + 加密 body。
- **哥斯拉 Filter/Valve 内存马**：插件体系全（虚拟终端、内网穿透、数据库管理），生成时直接选「内存马」类型。
- **流量加密代理型内存马**：Suo5 / Neo-reGeorg 的内存马模式——不出网环境下把内存马当正向代理用（衔接 05-03 隧道）。
- **自研要点**：filterName 随机（别叫 filterSecurity）；请求带特定 header/参数才激活，平时表现与正常组件无异；不报异常、不写日志。

## 5. PHP 内存马（不死马）

```php
<?php
ignore_user_abort(true); set_time_limit(0);
unlink(__FILE__);                       // 删自身
while (true) {
    file_put_contents('./.config.php', base64_decode('...shell...'));  // 循环写回马
    usleep(rand(50000, 500000));
}
```

- 原理：删掉的只是入口，循环进程持续把马写回磁盘——蓝队删了又长。
- 局限：PHP-FPM 多进程模型下需逐个进程处理，Apache mod_php 效果最好。
- 对策（蓝队视角）：杀进程而非删文件——所以红队要给不死马加「条件触发 + 随机 sleep」降噪。

## 6. .NET / IIS 内存马

- 原理：向当前 AppDomain 动态注册 `IHttpModule` / `IHttpHandler`，请求流经时执行。
- 注入通道：ViewState 反序列化（ysoserial.net）、Exchange Proxy 系 RCE（与 03-Exchange专项 联动——ProxyShell 后不落盘，直接注入 IIS 模块）、一次性 ashx 孵化。
- Exchange 场景落地即「全站请求过手」，配合 06 分册的通道加密。
- Exchange 环境的安装级步骤（反射注册 HttpModule、ashx 孵化器、w3wp 注入、IIS 原生模块五种方案与选型表）见 `03-Exchange专项.md` 第 8 节。

## 7. 蓝队怎么查 → 红队怎么藏

| 蓝队手段 | 工具 | 红队反制 |
| --- | --- | --- |
| 组件-文件对账 | java-memshell-scanner（c0ny1）扫 Filter/Servlet/Listener 无磁盘文件者 | 类名拟态（`org.apache.jsp.xxx`）、类加载器伪装 |
| 字节码反编译审计 | Arthas `sc *Filter*` / `jad` dump 可疑类 | 逻辑混淆、触发条件隐藏（不在类名/方法名露马脚） |
| Agent 加载检测 | `jcmd VM.command_line`、attach 审计 | 优先非 Agent 形态；必须用 Agent 时选值班低峰注入 |
| 重启大法 | 直接重启服务清内存 | 双通道：内存马 + 07 分册持久化，重启后自动回连 |

## 8. 使用场景决策

```text
打点成功 → 出站判断
  ├─ 可出站：内存马只做触发器 → 直接反弹 C2（06）
  ├─ 仅 HTTP 出站：冰蝎/哥斯拉内存马做加密通道
  └─ 不出网：Suo5/Neo-reGeorg 内存马做正向代理 → 进内网（05-03）
查杀环境：有 D 盾/河马/EDR → 内存马为首选落地形态
环境类型：Java 站 → Filter/Agent 型；IIS → Module 型；PHP Apache → 不死马
```

## 9. 实战纪律

- 注入前本地同版本中间件实测——注册代码对 Tomcat 7/8/9/10（javax→jakarta）有兼容差异。
- 一台机器只注入一种形态，多形态叠加增加暴露面。
- 记录注入的 filterName/类名进撤收清单（07 分册），演练结束必须清场。
