## 1. 知识点讲解

钓鱼的本质是「借用信任链」：信任的来源可以是域名（仿冒）、发件人（伪造/被盗账号）、上下文（内部话术）、**合法 IdP 页面**（用户自己在真站上点允许）。成熟度分三级：批量撒网（凭据收割）→ 鱼叉（定向个体）→ 鲸钓/商业邮件欺诈（BEC）。

红队视角的目标是拿到「有效会话/令牌或终端执行」，不是发出去多少封。2025–2026 的主战场已从「骗密码」扩到「骗授权」：AiTM 收 cookie、Device Code / Consent 收 token——**FIDO2/passkey 挡得住仿冒登录页，挡不住用户在真站上批准错误应用**。

## 2. 基础设施搭建

| 组件 | 要点 |
| --- | --- |
| 域名 | 仿冒三法：同形异字（rn→m、0→o）、加词（xxx-mail.com）、换 TLD；提前养域名年龄与分类 |
| 邮件信誉 | SPF/DKIM/DMARC 三件套必须配全；新域名先预热（小量正常邮件） |
| 投递通道 | 自建 postfix / 商业 ESMTP / 被盗邮箱（最像真的）；也可走 Teams/短信/二维码 PDF |
| 目标侧检测 | 先探测目标网关：发测试邮件看 banner、隔离策略、链接重写（Proofpoint/Mimecast 会重写 URL） |
| 云落地页 | OneDrive/SharePoint/Docs 外链作跳板时，信誉高但易留审计日志；授权范围内评估 |

## 3. 工具链（经典）

```bash
# gophish：群发与数据回收平台
# 流程：Sending Profiles(SMTP) → Landing Page(克隆登录页) → Email Template → Users&Groups → Campaign
# 要点：模板里 {{.URL}} 带跟踪参数；开启打开/点击/提交三事件

# evilginx2：AiTM（中间人钓鱼），可绕「传统 MFA」（收的是登录后会话 cookie）
evilginx2 -p /etc/evilginx2
config domain phish.example.com
config ip <vps_ip>
phishlets hostname o365 phish.example.com
lures create o365 → 生成钓鱼链接
sessions → 收割 cookie/token（直接导入浏览器即可登录）
```

AiTM 核心原理：反向代理真实登录页，转发用户与真实站点间的全部流量，窃取最终会话 cookie——用户本人完成了 MFA，攻击者拿走「登录结果」。对抗面：FIDO2 原点绑定、Conditional Access（设备合规）、Token Protection（会话绑设备）可显著抬高成本。

## 4. 身份窃取路径决策表（本册重点）

| 路径 | 原理一句话 | 对 MFA/Passkey | 典型工具/生态 | 何时优先 |
| --- | --- | --- | --- | --- |
| 静态登录页 | 克隆页收用户名密码 | 拦不住后续 MFA，常卡在第二步 | gophish 落地页 | 目标无 MFA / 只要密码喷洒弹药 |
| **AiTM** | 反代真站，收会话 cookie | 绕过 TOTP/SMS/Push；**FIDO2 通常可挡** | evilginx、EvilProxy、Tycoon2FA 等 PhaaS | 目标有 MFA 但未强制 FIDO2 |
| **Device Code** | 诱使用户把短码填到**真** `device login` 页，批准恶意应用 | **连 Passkey 也挡不住**（攻击点在授权层） | EvilTokens/ARToken、Kali365 等 | 目标启用 device code；开发者/CLI 密集租户 |
| Consent / OAuth 同意 | 诱使用户给恶意应用授权 | 同属授权层；与 ConsentFix 一类 | 恶意 App 注册 + 诱导同意 | 目标允许用户自助同意应用 |
| 附件/链接执行 | 终端落载荷再上线 | 与 MFA 无关 | HTML Smuggling → ISO/LNK 等 | 要码执行而非云会话 |

一句话：**先弄清授权范围要「会话」还是「shell」；要会话则在 AiTM / Device Code / Consent 里按目标 IdP 策略选型。**

### 4.1 Device Code 钓鱼（OAuth 设备授权滥用）

流程（原理级，不入库完整 PhaaS 面板）：

1. 攻击者向合法 IdP 发起 device authorization，拿到 `user_code` + 轮询用的 `device_code`。
2. 钓鱼页/邮件话术诱导受害者打开**官方**设备登录页，输入短码并点「允许」。
3. 攻击者轮询换取 access / refresh token（甚至后续 PRT 持久化——见公开 PhaaS 战报）。
4. 受害者全程在真域名上操作 → 邮件网关/URL 信誉难以阻断。

红队自测要点：授权租户上确认 device code 流是否被 Conditional Access 限制；实验室用自有测试应用演示，勿对真实生产用户发码。

### 4.2 Quishing（二维码钓鱼）与可信基础设施

- PDF/邮件内嵌 QR → 手机打开钓鱼页，绕过部分桌面网关链接重写与沙箱。
- 被盗 M365 账号 + SharePoint 托管诱饵文档：内信传播，信誉高。
- 防御启示（报告用）：出站邮件限速、收件箱异常规则、SharePoint 异常暂存监控。

## 5. 载荷形态（终端执行向）

| 载荷 | 说明 | 适用 |
| --- | --- | --- |
| Office 宏 | 经典，但默认禁用；用「启用内容查看」话术 | 老环境、内网办公 |
| LNK 快捷方式 | 双击执行 powershell/curl 拉二阶段 | 压缩包投递绕网关 |
| ISO/IMG/VHD 容器 | 历史问题：MOTW 未必传到容器内文件 | 主流替代 zip 的方案；新补丁后传播面收窄 |
| HTML Smuggling | JS 在浏览器端 Blob 拼装释放文件，网关看不到明文载荷 | 绕邮件沙箱；常与 ISO/LNK 二段组合 |
| OneNote/WSF/JS | 冷门格式过网关白名单 | 见招拆招 |
| 云盘外链 | 链接指向 OneDrive/Docs 再跳转，信誉高 | 链接重写对抗 |

免杀配合见 `06-02`；载荷投递前必在本地同类环境实测杀软反应。MOTW：以目标补丁级为准——「容器必脱 MOTW」已过时，须实测。

## 6. 话术设计要点

- 上下文来源：01-01/01-03 的情报（组织架构、近期事件、供应商关系、内部系统名）。
- 三钩子：紧急（限时）、权威（领导/IT/法务）、惯性（工资条/放假通知/系统升级/「设备登录验证」）。
- Device Code 话术常伪装：VPN/Teams/文档共享「验证码」、IT 安全检查、打印机/会议室设备绑定。
- 一封邮件只要一个动作；落地页与目标真实 SSO 页像素级对齐（AiTM）或干脆引导去真站（Device Code）。
- 时间选择：工作日上午 9-10 点、节假日前夕打开率最高。

## 7. 水坑与近源

- 水坑：控制目标员工常访问的行业站点/供应商页面，挂定向脚本（按 IP 段触发）。
- 近源（授权内）：恶意 USB、Wi-Fi 钓鱼门户（captive portal 收域账号）。

## 9. 红线

钓鱼是授权敏感区：目标人员名单、是否允许真实凭据/会话收集、演练窗口必须书面确认；收割的凭据/ cookie **只用一次验证有效性**，不翻邮件、不冒充发信、不做 BEC 欺诈；Device Code / 恶意应用注册仅在自有或书面授权租户。

### 2026-08-12 · Device Code 钓鱼工业化（PhaaS）

- **路径类型**：Device Code / 授权层
- **手法**：诱使用户在官方 device login 页输入短码并批准应用 → 攻击者换 token；攻击发生在认证之后，故 Passkey/FIDO2 无效；PhaaS（EvilTokens/ARToken、Kali365、Tycoon2FA 等）已标配
- **适用条件**：目标 IdP 仍允许 device code；用户可自助同意应用；常伪装 IT/文档/设备绑定话术
- **本地自测**：授权测试租户：Conditional Access 限制 device code 前后对比；勿对真实用户发码
- **局限**：不入库具体 kit 面板与完整诱饵页
- **链接**：https://thehackernews.com/2026/07/6-reasons-why-device-code-phishing-is.html · https://blog.talosintelligence.com/ir-trends-q2-2026/
