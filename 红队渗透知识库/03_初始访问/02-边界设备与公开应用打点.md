# 边界设备与公开应用打点

> 定位：用最小代价换**第一个内网落脚点**；本册讲决策与打法。  
> 漏洞编号与识别特征权威表：[`../09_漏洞库/03-边界设备漏洞速查.md`](../09_漏洞库/03-边界设备漏洞速查.md)（**09-03**）；通用 Web/OA/中间件仍见 [`../09_漏洞库/01-高危漏洞速查（打点向）.md`](../09_漏洞库/01-高危漏洞速查（打点向）.md)。  
> Exchange 深度链见 `03-Exchange专项.md`；落地形态见 `04-内存马专项.md`；身份绕行见 `01-钓鱼与社会工程.md`。  
> **周更**：边界 1Day/在野 → 周报 **3.8** → 回链 09-03 时效；手法级纪律可追加本文「时效条目」。

## 1. 知识点讲解

打点的本质是「用最小的代价换第一个代码执行点」。优先级排序：

**已知 Nday 未修的边界设备（预认证）> 管理面误暴露 + 默认口令 > 公开应用未授权 > 通用 Web 洞 > 钓鱼绕行。**

边界设备（VPN、防火墙、邮件网关、ADC、堡垒机）权重最高：权限高、网络位置好、补丁滞后、一打即进内网。  
许多「打不动主站」的目标，真正的软柿子在 **SSLVPN / 负载均衡管理口 / 旧版网关**。

## 2. 打点决策流程

```text
资产指纹（httpx + 测绘语法 01-02）
  → 是否边界产品？（VPN/ADC/防火墙/堡垒机/邮件网关）
       是 → 查 09-03（版本+识别特征）→ 有洞？
              有 → 授权范围内最小验证 → 利用 → 落地 → 本机情报三件套
              无 → 管理口暴露？默认口令/未授权 API？
       否 → 查 09-01（中间件/OA/协作）→ 同左
  → 仍无 → 通用漏洞（02 分册）或换资产 / 转 03-01 钓鱼
```

铁律：主站 WAF 很厚时，**先扫同证书/同 ICP/同网段的 VPN 与运维入口**，不要死磕营销站。

## 4. 指纹与测绘（边界专用）

```bash
# 探活 + 标题/技术栈
httpx -l edges.txt -title -td -sc -favicon -tls-grab -o edge_httpx.txt

# 常见 VPN/网关路径（示例，按授权范围裁剪）
# /remote/login  /dana-na/  /global-protect/login.esp  /tmui/login.jsp
# /logon/LogonPoint/  /+CSCOE+/  /vpn/index.html

# 测绘思路（语法见 01-02）：产品名 + 标题 + favicon hash + SSL 证书组织
# 同证书找「门户 vs 管理口」两套主机
```

识别清单：

1. **标题 / Server / 证书 OU** 是否厂商名。  
2. **特色路径** 是否 200/302（不要只看首页）。  
3. **版本线索**：登录页 HTML 注释、JS 路径版本号、`X-*-Version` 头。  
4. 管理口与门户是否同主机不同端口（10443/8443/4443 等）。

## 5. 验证到落地的标准动作

1. **指纹识别**：与 09-03 表交叉；版本不确定时先标「疑似」再最小验证。  
2. **最小验证**：优先版本比对与无害探测（连通性、公开错误页差异）；有回显再用 `id`/`whoami` 级证明。  
3. **shell 落地三选**：  
   - 设备/Appliance 上可能是**受限 shell** 或诊断命令通道——先稳定出网再谈工具；  
   - 若落到后挂 Web/跳板机：文件马 / 内存马（Java 见 03-04）/ 纯命令通道；  
   - 出站白名单决定：反弹 vs HTTPS 隧道 vs 仅正连（05-03）。  
4. **出站判断**：`ping`/`curl` DNSLog；VPN 设备常只能特定端口出站。

## 6. 打点后的第一件事（衔接内网）

```bash
# 就地情报三件套（按 OS/设备裁剪）
ipconfig /all & netstat -ano & tasklist        # Windows 跳板
ip a; ss -antp; ps aux                         # Linux
# 设备侧优先：路由表、隧道用户、LDAP/AD 配置、下游防火墙策略、证书与 VPN 池网段
```

原则：边界机器本身是情报富矿（内网网段、运维账号、域信息），**先翻本机再扫内网**。

## 7. 与钓鱼 / 通用 Web 的分工

| 路径 | 何时选 |
| --- | --- |
| 边界 Nday（本册 + 09-03） | 测绘已命中高危产品且版本匹配 |
| 公开应用 / OA（09-01） | 无 VPN 洞但有协作套件暴露 |
| 钓鱼（03-01） | 边界与 Web 皆厚；或需云会话/令牌 |
| 云元数据 / AK（08） | SSRF 或泄露已指向云身份 |

### 2026-08-12 · 边界专册与周更 3.8 挂接

- **产品族**：VPN / ADC / 防火墙 / 堡垒机（总览）  
- **手法**：边界权威表迁至 09-03；周报硬性专扫 3.8；打点决策「先边缘后主站」。  
- **适用条件**：授权打点；公网或准公网运维面。  
- **本地自测**：实验室用公开镜像/厂商试用只练指纹与版本匹配，不练破坏性利用。  
- **链接**：见 `维护/每周更新SOP.md` §I；`09_漏洞库/03-边界设备漏洞速查.md`

### 2026-08-15 · 客户端 VPN 面 + 厂商「DoS」描述不可信上限

- **产品族**：GlobalProtect App / NetScaler Gateway（SAML）
- **手法**：① 门户补丁与**客户端构建号**分开记；CBL+SAML 是另一条初始访问面。② 公告写 Memory Overflow/DoS 且补丁加的是预认证拷贝长度检查时，按内存破坏排期，不直接忽略。
- **适用条件**：授权打点；能指纹门户且能问到客户端版本/预登录策略
- **本地自测**：资产表增加两列：客户端版本、是否 SAML CBL / 是否 Gateway+SAML
- **链接**：当周周报 3.7/3.8；09-03 时效 2026-08-15

### 2026-08-29 · Windows IKE 也是边界；NetScaler 按 KEV 排期

- **产品族**：Windows IKEv2；Citrix NetScaler；FortiManager
- **手法**：① 测绘增加「公网 UDP 500/4500 的 Windows 应答器」列，不要默认只有盒子 VPN。② CVE-2026-8452 已入 KEV，厂商「DoS」描述不再当上限。③ FortiManager FGFM 先问 `fgfm-peercert-withoutsn`，默认关则 70468 不是打点面。
- **适用条件**：授权打点；能扫 UDP IKE 或指纹 Gateway/SAML / FortiManager
- **本地自测**：资产表增加 IKE 暴露与「FGFM 是否跳过序列号」两列
- **链接**：当周周报 3.8；09-03 时效 2026-08-29

### 2026-09-19 · SMA 预认证 SSRF；ISE/FMC 管理 API；NetScaler 看 SAML 门槛

- **产品族**：SonicWall SMA1000；Cisco ISE/FMC；Citrix Gateway
- **手法**：① SMA 未打 09-01 热修按**已失陷**（83548 预认证）。② ISE/FMC 认证绕过**与盒子配置无关**，测绘增加「身份/防火墙管理面」列。③ NetScaler 19490：旧构建「有 Gateway/AAA 就打」，新构建还要 `samlAction`——先读版本再假设预认证。
- **适用条件**：授权打点；能指纹 SMA 固件 / ISE 管理口 / Gateway 构建号
- **本地自测**：资产表增加 SMA 热修号、ISE/FMC 是否公网、NetScaler 是否含 SAML action
- **链接**：09-03 时效 2026-09-19

### 2026-08-18 · FortiOS 不只 SSL-VPN：显式代理也是面

- **产品族**：FortiGate / FortiOS 显式 web-proxy
- **手法**：资产表不要默认「有 Forti 就是 `/remote/login`」。问有没有开 **SOCKS + Kerberos** 的显式代理；CVE-2026-71407 是 WAD 预认证内存面，但配置门槛高，按观察排期而非 P0 打点
- **适用条件**：测绘命中 FortiOS 7.6.1–7.6.6 且运维承认显式代理
- **本地自测**：指纹阶段多问一列「显式代理/SOCKS」；未命中组合则忽略本 CVE
- **链接**：https://fortiguard.fortinet.com/psirt/FG-IR-26-161

### 2026-08-15 · Nday 仍付赎金 + Ivanti 不止 Connect Secure

- **产品族**：Fortinet SSL-VPN；Ivanti EPM / MDM
- **手法**：① CISA 确认 Gunra 2026 仍打 2024/2025 FortiOS 认证绕过；未修按失陷假设（新账户、异常会话、**流量控制/认证文件被改**）。② 扫 Ivanti 时 Connect Secure 与 EPM/MDM **分开建档**——月更可能只打管理/Agent 面。
- **适用条件**：授权打点；测绘命中 FortiGate 或 Ivanti 任一产品
- **本地自测**：资产表增加「产品线」列（ICS vs EPM vs MDM）；Fortinet 未修实例列「失陷检查」而非只列补丁号
- **链接**：https://www.cisa.gov/news-events/cybersecurity-advisories/aa26-222a · Ivanti 08-11 月更
