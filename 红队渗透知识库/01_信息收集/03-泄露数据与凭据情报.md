# 泄露数据与凭据情报

## 1. 知识点讲解

泄露情报的价值在于「不劳而获的凭据与资产地图」。三类来源：①公开泄露库（邮件:密码 组合）；②代码与文档泄露（GitHub、网盘、文库、pastebin）；③黑产交易渠道（BreachForums 及镜像、TG 频道——只检索不交易，注意法律红线）。合规边界：检索与验证公开泄露中「是否涉及目标资产」属情报收集；下载、买卖、使用他人数据需在授权与法律框架内。

## 2. 检索路线

```text
目标域名/公司名/邮箱后缀
  → ① haveibeenpwned / dehashed / IntelX（按域名查泄露事件）
  → ② 公开泄露库镜像（Collection #1-5、COMB、RockYou2021 等合集）
  → ③ GitHub/GitLab/Gitee 代码泄露
  → ④ 网盘（百度/阿里/夸克）与文库（豆丁/道客）关键词
  → ⑤ Telegram 公开频道、Onion 站点情报
```

## 3. GitHub 泄露检索语法（高频）

```text
"example.com" password
"example.com" (api_key OR secret OR token OR ak OR sk)
"mail.example.com" (smtp_password OR授权码)
filename:.env DB_PASSWORD
filename:config.php "example.com"
"example.com" "BEGIN RSA PRIVATE KEY"
extension:sql "example.com"
org:目标组织 language:properties
```

技巧：搜公司中文名/拼音/缩写/内部系统代号（从招聘 JD 里挖）；按最近 push 排序抓「新鲜泄露」。

## 4. 凭据情报的加工与使用

| 加工步骤 | 说明 | 产出 |
| --- | --- | --- |
| 提取目标域邮箱 | 按域名过滤泄露库 | 员工邮箱清单 |
| 格式标准化 | 邮箱:密码、去重、去无效 | 凭据对 |
| 密码模式分析 | 公司名+年份、键盘走位、生日 | 定制字典 |
| 合规使用 | 仅在授权范围做密码喷洒/钓鱼铺垫 | 初始访问 |

密码喷洒原则（防锁）：每账户 ≤2 次/小时、错峰、先试一个通用口令测锁定策略（详见 05-02）。

## 5. 泄露情报还能给什么

- 历史泄露中的内部文档：组织架构、系统截图、VPN 使用手册——都是钓鱼素材与内网地图。
- 供应商/外包泄露：目标没被打穿，但给目标做运维的公司被打穿了（供应链视角）。
- 数据库泄露中的表结构：推断业务系统栈，指导后续打点。

## 6. 使用场景

- 打点无门时：查泄露库有没有目标域员工凭据 → 合规喷洒/撞库（须授权）。
- 钓鱼准备：泄露的组织架构与通讯录 → 精准鱼叉对象清单。
- 报告增值：把「目标在 X 次公开泄露中出现 Y 条凭据」写进报告，是最直观的风险证据。

## 自测锚点

- [ ] 能给一个域名列出 ≥4 条泄露情报检索路径并实际执行。
- [ ] 能从泄露凭据中分析出目标公司的密码习惯并生成定制字典。
- [ ] 能说明泄露数据使用的授权与法律边界（哪些能做、哪些不能做）。
