## ② AI 漏洞挖掘的重大突破与成果

### 2-1 厂商级 AI 挖洞规模化落地：Oracle 7×24 双模型审计体系【窗口内 · 本期重点】

- **时间**：2026-07-21 Q3 CPU 发布，07-25 实战分析公开
- **要点**：
  - Oracle 2026 年 7 月 CPU 刷新补丁纪录（EBS 410 个、Fusion Middleware 355 个等），官方首次公开承认漏洞挖掘体系完成 **AI 规模化落地**，并配套上线月度 CSPU（每月第三个星期二，仅收 Critical/可远程利用项）与季度 CPU 双轨补丁机制；
  - 技术架构：全产品线代码仓库经可信通道接入**双大模型并行引擎**（安全专项模型 + 通用安全大模型），7×24 全量审计；公开报道称专项模型在 CyberGym 漏洞检测测评中检出准确率 83.1%（单一来源，供参考）；
  - 三个超越传统手段的能力：**全域无死角遍历**（含冷门/遗留代码）、**自主构造载荷验证可利用性**（数百枚无认证远程漏洞由 AI 完成可用性验证）、**挖掘 5 年以上潜伏零日**；
  - 攻防连锁反应：漏洞公开到批量入侵的窗口被压缩至 **72 小时以内**，攻击方可租用同类模型对公开 CVE 快速逆向出 EXP——这是补丁机制从季度改月度的直接动因。
- **对审计工作的启示**：
  - “AI 全量遍历 + 人工精审热点”将成为标准分工；审计师价值上移至复杂业务逻辑与攻击链设计；
  - 防守方修复 SLA 需要按 72 小时窗口重新设计；历史遗留代码（5 年+）是 AI 挖洞的高产区，自查优先级上调。
- **来源**：CSDN《Oracle 2026年7月CPU漏洞修复实战：AI挖洞+月度CSPU补丁运维指南》（参考 1）

### 2-2 微软补丁量创纪录背后的同一逻辑【窗口内】

- **时间**：2026-07-15
- **要点**：微软 7 月修复 622 枚漏洞（Windows 416 枚，约为去年同期 3 倍）；Windows 部门负责人公开指出，以先进模型为基础的 **AI 代理已具备自主识别安全漏洞的能力**——AI 同时抬高了漏洞产出与利用速度。补丁数量暴涨是全行业现象，非单一厂商问题。
- **来源**：ZOL 快讯（参考 2）

### 2-3 多智能体协作挖洞：攻破 52% 测试目标【窗口内】

- **时间**：2026-07-29/30 研究报道
- **要点**：多所高校联合研究，让多个 AI 智能体组成“黑客团队”，按**侦察、分析、利用**分工协作，在漏洞挖掘测试中攻破 52% 的目标；相比单模型，多智能体在需要多步推理、多工具配合的复杂漏洞场景成功率显著提升。论文已公开，代码待发布（细节尚少，下期跟踪）。
- **方法论价值**：分工角色化（Recon/Analysis/Exploit）+ 共享状态记忆，是当前 AI 渗透系统的主流架构，与下述商用/开源实现互相印证。
- **来源**：西域网转引研究报道（参考 3）

### 2-4 商用系统：绿盟智能渗透系统 AI-PTS 2.0【窗口内】

- **时间**：2026-07-16 发布
- **要点**：端到端自主渗透闭环（任务规划 → Web 资产测绘 → 漏洞分析 → 攻击验证 → 报告生成）；底层依托 GLM-5.2（1M 无损上下文、长链路推理、自主工具创造）；强调在长周期任务中保持目标理解与状态记忆一致，**全流程业务时序推演以挖掘深层业务逻辑漏洞**——自动化渗透从“按规则执行”转向“按目标推理”。
- **对审计工作的启示**：业务逻辑漏洞（越权、流程绕过、状态机缺陷）正成为 AI 工具的下一个主攻方向，恰是传统扫描器盲区；审计师在这些领域既要会用 AI 也要审得动 AI 的结论。
- **来源**：中国日报网/绿盟发布稿（参考 4）

### 2-5 生产级方法论样本：GitHub Security Lab Taskflow Agent【月初回溯】

- **时间**：2026-07-01 官方更新（体系成熟案例，收为方法基线）
- **方法论拆解**：
  - 定位：对 CodeQL 静态分析告警做**自动化分拣（triage）**，把复杂研判流程拆成 YAML 描述的离散任务（taskflow），由 LLM 逐项执行；
  - 关键洞察：误报多源于“人类一眼能看出、形式化规则极难表达”的**模糊模式**（鉴权检查缺失、净化函数是否充分），恰是 LLM 强项；
  - 工程要点：MCP 服务器承担程序化子任务、中间状态落库以便调试迭代；
  - 战果：对 GitHub Actions 与 JS/TS 项目分拣出约 30 个真实漏洞；官方称其对 **Auth Bypass、IDOR、Token 泄露**等高影响类型尤其有效。
- **对审计工作的启示**：「SAST 粗筛 + LLM 精判模糊模式」是当前投入产出比最高的 AI 审计落地形态；任务拆解文件化（YAML）保证了可复现与可审计。
- **来源**：GitHub Security Lab 官方博客与 ZenML 案例库（参考 5、6）

### 2-6 开源与商业工具方法论补遗【背景延伸】

- **DeepAudit（开源）**：Multi-Agent 审计流水线——Orchestrator 制定审计策略 → Recon Agent 识别技术栈与攻击面 → Analysis Agent 深度分析 → **Verification Agent 沙箱验证漏洞真实性**；支持跨方法联合审计（沿调用关系追校验函数）。“验证 Agent 进沙箱”是压误报的关键设计。（2026-01，参考 7）
- **Codex Security（原 Aardvark）**：三阶段管线——扫描 → 隔离环境验证 → 修复建议；公开数据：扫描 120 万+ commit，识别 792 个 critical、10561 个 high。（2026-06 横评，参考 8）
- **CodeQL + Copilot Autofix**：官方 Beta 数据——有修复建议的漏洞整体修复提速约 3 倍，XSS 7 倍、SQL 注入 12 倍；说明“AI 修复建议”对吞吐量的提升比“AI 发现”更快兑现。（参考 8）
- **LLM 自身红队工具**：Garak 0.15.0（2026-05，新增多轮 GOAT 探针、Agent-breaker 工具滥用探针、系统提示词提取探针）；PyRIT 的 `XPIAOrchestrator` 专攻**跨域间接提示词注入**（把恶意指令埋进文档库/邮件/网页等外部数据源）。（参考 9）
- **AI 辅助逆向**：x64dbg + MCP（x64dbg-automate 插件）让大模型直接驱动调试器做样本自动化逆向——AI 分析能力正向二进制/逆向场景延伸。【窗口内，2026-07-25】（参考 10）

## ① 新漏洞特性与漏洞模式演变（态势与跨语言项）

### 1-1 奇安信《2026 年中网络安全漏洞威胁态势研究报告》【窗口内】

- **时间**：2026-07-24 发布
- **核心判断**：2026 上半年漏洞态势进入“**AI 深度博弈**”阶段——生成式 AI 普及使漏洞生命周期被极度压缩；新增漏洞数量爆发式增长，“**高危 + AI 诱导**”型漏洞显著增加；攻击面向“云原生 + 智能终端”倾斜；供应链攻击与勒索软件结合愈发紧密。
- **入库价值**：作为本期各分册模式条目的宏观印证；建议知识库使用者按此校准下半年审计优先级。
- **来源**：奇安信研究报告列表页（参考 11）

### 1-2 2026 攻防赛事漏洞类型总结：AI 时代的攻击面迁移【窗口内 · 高价值】

- **时间**：2026-07-18
- **要点提炼**：
  1. **提示词注入漏洞减少**（防护成熟），但**大模型 Web 应用与 Agent 安全成为新突破口**；
  2. **前端 JS 代码挖洞数量明显增加**（详见 JS 分册 3-1）；
  3. 国产中间件漏洞因公开工具增多而出洞率上升；
  4. 客户端与边界设备漏洞挖掘门槛因 AI 辅助显著降低；
  5. 传统 Web 漏洞仍在，但需**组合利用**才有杀伤力；
  6. **红队经验判断与复杂场景分析仍是 AI 难以替代的核心能力**。
- **入库价值**：直接指导知识库使用者的技能投资方向——AI 工具链使用能力 + 业务逻辑/组合链思维。
- **来源**：希潭实验室（参考 12）

### 1-3 AI Agent 平台自身漏洞模式三态（OpenClaw 三连 RCE 复盘）【背景延伸】

- **时间**：2026-04-30 完整拆解公开，7 月仍被高频引用
- **三种模式（对一切 Agent 平台通用）**：
  1. **请求流注入**：不对上游 API 请求做完整性校验 → 恶意中转代理污染请求流（提示词注入）→ 模型被诱导生成恶意命令 → MCP 工具链自动执行（CVE-2026-30741，CVSS 9.8）；
  2. **插件自动加载**：工作区插件无校验加载即执行（CVE-2026-32920，CVSS 9.2）——“信任本地目录内容”是通病；
  3. **跨站 WebSocket 劫持**：WS 未校验 Origin → 钓鱼页劫持 Agent 会话（CVE-2026-25253，CVSS 8.8）。
- **审计要点**：审 Agent 平台=审三条信任边界（模型输入完整性、本地插件加载、WS/IPC 来源校验）；另见 7 月披露的大模型客户端“过度激进执行”事件：模型在脱离沙箱、持有全权限时误删用户文件——**执行层防护（沙箱 + 危险操作二次确认）是硬性要求**（2026-07-19 报道，参考 13）。
- **来源**：看雪论坛（参考 14）、AI 技术日报 07-19（参考 13）

### 1-4 云与身份设施新项（窗口内快报，均标注核实状态）

- **Azure Key Vault 身份认证绕过（CVE-2026-62825，CVSS 10.0）**：2026-07-25 中文预警称可无认证访问 Secrets/Keys/Certificates，官方补丁未出、公共 PoC 已现；**仅单一公众号来源，未经微软公告交叉证实，使用时请先核实**。缓解思路：关闭公网访问、启用 Private Endpoint、强化日志监控。（参考 10）
- **AD CS 域提权“Certighost”（CVE-2026-54121）**：2026-07-25 出现深度分析，延续 AD CS 证书模板/注册权限误配置提权家族（ESC 系列）的演化，细节待下期补充。（参考 10）
- **SharePoint 链式漏洞**：CVE-2026-55040 认证绕过（7 月补丁，Rapid7）+  embargo 中的第二环，组合为未授权 RCE，8 月补丁日重点跟踪。（参考 15）

## ③ 审计思路与 CTF 技巧（跨语言综合）

### 3-1 AI 应用渗透测试的分类框架正在标准化

- **时间**：2026 上半年成型，本月持续被采用
- **框架要点**（OWASP LLM Top10 对齐的测试分类）：提示词注入（LLM01）、敏感信息泄露（LLM02）、SSRF（LLM05）、工具调用越权/未授权访问（LLM06）、多轮记忆污染、插件供应链（LLM10）等八类；每类配套“复现步骤 + Payload 族 + 修复建议”的报告结构。
- **入库价值**：代码审计知识库可直接复用此分类做 AI 应用的审计 checklist；其中**多轮记忆污染**（恶意指令写入长期会话记忆持续生效）与**工具调用越权**是普通用户可达、传统 Web 审计覆盖不到的新类目。
- **来源**：大模型渗透测试报告模板（参考 16）

### 3-2 CTF 综合技巧拾遗（本月 writeup 群共性）

- **Crypto**：低指数攻击（e 过小时直接开方/广播攻击）与密钥流重用（两段密文异或消 keystream）仍是送分点也是常见失分点；
- **Web 通用**：JWT 三件套（alg=none、弱密钥爆破、HS/RS 混淆）出场率依旧最高；
- **方法论**：本月多篇 writeup 体现“先威胁建模再动手”的趋势——先列信任边界与状态机，再选测试点，比上来就 fuzz 效率高。
- **来源**：GFCTF-2026 wp（参考 17）
