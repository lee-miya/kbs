## ① 新漏洞特性与漏洞模式演变

### 1-1 Go 工具链与运行时自身漏洞两则【月初回溯】

- **时间**：阿里云漏洞库 2026-07-09 快照收录
- **条目**：
  - **CVE-2026-39817**：`go tool pack` 调用时未清理 `cmd/go` 中的输出路径（CWE-787 越界写）——构建期工具链漏洞，提醒关注 CI 构建环境的工具版本；
  - **CVE-2026-33811**：`net` 包处理超长 CNAME 响应时崩溃（DoS）——DNS 解析路径对畸形响应的健壮性缺陷，任何对外发起 DNS 查询的 Go 服务均受影响。
- **审计要点**：Go 项目的供应链基线应包含**工具链自身版本**（go 编译器、net 标准库）；对外暴露 DNS 解析的服务建议跟进官方修复版本并加 panic recover 兜底。
- **来源**：阿里云漏洞库 golang 产品页（参考 1）

## ③ 审计思路与 CTF 技巧

### 3-1 Go 代码审计高频风险清单（静态扫描视角，本月审计报告复核整理）

- **来源**：zkEVM 审计报告（Govulncheck + 静态扫描方法论）
- **Go 专项危险面清单**：
  - 硬编码凭证；监听 `0.0.0.0` 全接口；
  - `err` 未检查（Go 特色：错误被静默丢弃导致逻辑绕过）；
  - `strconv.Atoi` 结果强转 `int16/32` 的**整数截断溢出**；
  - 解压炸弹（zip/tar 解压未限大小/比例）与**压缩包内路径穿越**；
  - `net/http` 未设超时（慢请求 DoS）；
  - SQL 用 `fmt.Sprintf` 拼接；命令执行参数可控；
  - 文件路径作为污点输入直接进入 `os.Open`；
  - 弱算法 DES/RC4/MD5/SHA1；TLS 配置不当；RSA 密钥 <2048；
  - `math/rand` 当安全随机数用（应 `crypto/rand`）；
  - 切片/数组越界访问。
- **审计要点**：Govulncheck（依赖）+ gosec（代码模式）双跑是基线；人工审计优先看 `err` 丢弃与类型截断这两类工具覆盖弱的逻辑层问题。
- **来源**：ScaleBit《B² Network zkEVM Final Audit Report》（参考 2）

### 3-2 Go Web 审计经典模式复盘：“写 401 但不 return”式鉴权失效（Gitea LFS 链）

- **背景**：该漏洞链今年被新文章重新讲解（社区复习热度高），模式在 Go Web 项目中反复出现，收为审计基线。
- **链式结构（模式级）**：
  1. **鉴权失败不中断**：`if !authenticate(...) { requireAuth(ctx) }`——`requireAuth` 只写 401 头和状态码，**函数没有 return，后续业务逻辑照跑** → 未授权创建对象；
  2. **ID 未过滤 → 目录穿越**：对象 ID 直接 `filepath.Join` 拼接，`../` 穿越任意读；
  3. **配置文件泄露密钥 → JWT 伪造**：读到服务端配置中的签名密钥后伪造 JWT 获得完整读写；
  4. **条件竞争写文件**：利用“先写临时文件、校验失败 defer 删除”的窗口，竞争持有临时文件实现任意写；
  5. **文件型 session 反序列化**：向 session 路径写入 Gob 序列化数据伪造身份提权。
- **审计要点**：
  - Go Web 中间件/鉴权函数必须确认“失败后是否真正中断流程”（`return`/`Abort`/panic 链），这是 Go 生态独有的高频坑；
  - `filepath.Join` 不防穿越（会清洗但不拒绝 `..`），ID 类参数要先做字符集白名单；
  - “先写临时文件再校验”的模式天然带竞争窗口。
- **来源**：Go 代码审计学习系列（参考 3）；经典链分析（参考 4）
