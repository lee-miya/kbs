# 代码审计知识库 · 总索引

> 定位：跨项目复用的代码审计弹药库。按语言对照「危险特征 → 审计要点 → Checklist」，辅以通用方法论与 AI 挖洞态势。  
> 加载入口：先读本文件旁的 [`INDEX.md`](INDEX.md)（速查表），再按需打开 1～2 个分册。  
> 红线：只收公开知识；项目细节永不入库。体例见 [`../维护/文档体例约定.md`](../维护/文档体例约定.md)。

## 二、场景 → 分册

| 你的任务 | 建议打开 |
| --- | --- |
| 任意项目开工 | 通用方法论 → 对应语言分册 |
| 审计 PHP / Java / Python / Node / Go | 该语言分册 + 通用方法论 |
| 二进制 / fuzz | C/C++ 分册 + 通用方法论 |
| 补丁 diff / N-day 逆向 | 通用方法论（六步法）+ 语言分册 |
| 借鉴 AI 挖洞 / 审 Agent 平台 | 综合分册 + 通用方法论 |
| 授权渗透里的 Web 打点手法 | 转到 [`../红队渗透知识库/02_Web渗透`](../红队渗透知识库/02_Web渗透)；根因回本库语言分册 |

## 三、与红队库的分工

| | 本库（审计） | 红队库 |
| --- | --- | --- |
| 视角 | 源码 / 组件 / 模式 | 场景 / 命令 / 作战流程 |
| 时效入口 | `增量池/` → 分册「时效条目」 | `12_每周情报/` → `09_漏洞库` 等 |
| 自学 | 各册 Checklist | `11_自学体系` 能力清单 |

同一主题两库都有时：**先红队会用，再审计会找**。

## 四、更新机制

1. **每周一**：按仓库 [`维护/每周更新SOP.md`](../维护/每周更新SOP.md) 写增量 → 有价值的回链「时效条目」→ 更新 `INDEX.md` 日期。
2. **项目沉淀**：研究结束只提炼可公开模式入库。
3. **即时入库**：对话中说「这条入库」→ 写成条目合并进对应分册。

分册是权威版本；`增量池` 只供溯源，使用时不要直接当教材加载原料。
