# 通用审计方法论（跨语言，开工必读）

> 任何项目开工前先读本册，再按语言拉对应分册。
> 更新：2026-09-19（v1.7：Host/Bearer 不作信任根；AISLE 冷门分支；Harness loopback）

---

## 一、三条审计路径（按项目阶段选择）

1. **攻击面枚举 → sink 回溯（推荐开局）**：先列全部入口（路由、参数、文件解析、RPC、定时任务），再找全部汇聚点（sink），逐对回溯"入口数据能否到达 sink"。覆盖面最全。
2. **source → sink 正向追踪**：从某个具体入口参数出发，跟踪它流经的所有函数，看落到哪些 sink。适合深挖单一功能（如上传链路）。
3. **模式匹配（grep 驱动）**：按分册"危险特征"全文检索，命中即回溯。速度最快，适合老代码与 N-day 排查，但会漏逻辑漏洞。

实战节奏：开局用 1 建全局图，深挖用 2，扫尾用 3。

## 二、入口与汇聚点通杀表

| 入口（source） | 汇聚点（sink） |
|---|---|
| GET/POST/COOKIE/Header（含 X-Forwarded-*） | SQL 执行、命令执行、代码执行 |
| 上传文件（文件名/内容/解压成员名） | 文件写、include/require、模板渲染 |
| URL 跳转/回调地址、webhook | SSRF 请求发起、XXE 解析 |
| 序列化数据（body/cookie/缓存/session） | 反序列化、表达式求值 |
| 邮件头像/二维码/图片处理、导入导出 | 重定向、日志（配合包含/二注入） |
| RPC/消息队列/定时任务参数 | 数据库写后读（二次注入源头） |

**纪律**：先把这张表按目标代码填成"项目版"，再开始逐点审计。填表过程本身就是一半审计。

## 三、补丁 diffing 六步法（N-day 逆向与未披露漏洞挖掘）

1. **拿版本对**：官方仓库取修复前后两个 tag（或源码包），`git diff` / `diff -ruN` 得补丁。
2. **定位安全相关改动**：优先看新增转义、权限判断、随机数替换、危险函数删除；过滤掉文档/重构噪音。
3. **反推触发路径**：从被修补的函数反向找调用链，确认用户输入如何到达（文件:行号记录）。
4. **判定可达性**：是否需要认证？参数经过哪些过滤？过滤能否绕过（宽字节/双重编码/数组）？
5. **构造最小验证**：在未修复版本环境上，用最小请求触发；先证明到达 sink（日志/回显/时间差），再谈利用。
6. **评估与武器化**：定级（未认证+高危优先），按需完成 PoC → WebShell 的完整链。

**注意**：官方补丁常"打掩护"——一个安全修复混在多个普通 commit 里，且 commit message 不写安全字样。所以按时间窗全量 diff，不要只看 security advisory。

**失败路径（fail-open）检查**：安全边界若写作「先解密/验签/鉴权，再处理」，必须确认失败时 **return/丢弃/抛错中止**，而不是只记日志后继续把原始输入送入 sink。2026-08 Tomcat EncryptInterceptor 回归（CVE-2026-34486）是典型课：一行控制流挪出 try，加密拦截器变成空壳。对「安全补丁本身」做二次 diff 时，优先看 catch 后是否仍到达反序列化/命令执行。

## 四、假设-验证循环纪律（防幻觉、防空转）

- 每条漏洞假设必须落到 **文件:行号 + 触发请求**，禁止"理论上可能存在"写入产出。
- 验证分级：A 级（完整利用/WebShell 落地）> B 级（sink 可达，回显/时间差证据）> C 级（代码推理成立但环境未验证，必须如实标注）。
- 一个方向连续 3 次验证失败，停下来重新枚举攻击面，不要在死胡同加码。
- 每完成一个阶段立即固化（脚本、PoC、交接简报），上下文比结论更值钱。

## 五、漏洞链组合法（目标树）

以终为始画目标树：顶层目标（WebShell/RCE）→ 分解为必要条件（能写文件？能执行？有上传点？有后台凭据？）→ 每个条件用一个低危填补：
- 存储型 XSS + CSRF → 钓管理员 → 后台模板编辑 getshell
- 信息泄露（备份/源码）→ 拿密钥 → 伪造 session/JWT → 越权 → 上传
- 任意文件读 → 读配置拿数据库 → 二次注入/写文件权限 → getshell
**经验**：单个中低危不急着报，先想"它能当哪条链的跳板"。

## 六、环境与复现纪律

- 靶标用 docker 或脚本化部署，**版本与漏洞声明严格一致**；改一行配置都要记录。
- 复现全程日志留痕（时间、请求、响应、证据），日志即报告素材。
- 环境打完即快照；交接给别人（或给未来的自己）靠构建脚本 + 交接简报，不靠记忆。

## 七、产出物规范（每个漏洞）

1. 受影响版本范围（精确到 tag/commit）
2. 漏洞交互流程（攻击者 ↔ 服务端完整步骤，含请求报文）
3. 安全影响（能做什么、前置条件、是否未认证）
4. 验证证据等级（A/B/C，如实标注）
5. 修复建议（对照官方补丁或给出代码级方案）

## 十、时效条目（周更回链）

> 跨语言方法论级新纪律追加于此；语言特有模式进对应语言分册。

### 2026-08-09 · 安全边界 fail-open（已写入第三节补丁 diff 注意）

- 见上文「失败路径（fail-open）检查」；典型课 CVE-2026-34486。
- 自测：任选一处「catch 后继续处理输入」的公开示例代码，标出应加的中断点。

### 2026-08-15 · 弃用仍接线 + ACL 单段通配（UIUCTF Nabi AI）

- **危险特征**：类型/文档标 deprecated 但服务端仍读取；密钥/策略路径用 `+`/`*` 图省事。
- **审计要点**：① 「标了弃用」必须对照实现是否已断开；② Vault/IAM/路由通配按**段**理解，不要当「只匹配本意资源」；③ 生产源码图默认当攻击面。
- **自测**：任选一处 optional/deprecated 入参，标出服务端是否仍进入 sink；对照一条通配策略能否收成字面路径。
- **链接**：综合分册「CTF 拾遗」Nabi AI；Node 时效 2026-08-15。

### 2026-08-29 · 缺失字段回落禁止默认方法分发（GitLab GraphQL）

- **危险特征**：为滚动发布合成「未来字段」时，未知字段名落到框架默认 `public_send` / 反射 getter，而不是显式空 resolver。
- **审计要点**：① 任何「schema 没有的名字」路径必须失败或恒 null；② 版本过滤指令只应裁剪文档，不应打开任意方法面；③ 与 Nacos「注解缺键过滤器不认」同属**元数据不完整 = fail-open**。
- **自测**：找出一处动态字段/方法名来自请求的 GraphQL/RPC 回落，标出是否有 allowlist。
- **链接**：当周周报；GitLab 19.2.4 补丁说明。

### 2026-08-18 · CI `run:` 内插 GitHub 上下文（Wiz / Snowflake）

- **危险特征**：工作流 `run:` / `script:` 字符串里出现 `${{ github.event.issue.title }}`、`github.event.comment.body`、`github.event.pull_request.title` 等不可信上下文；先 `echo '...'` 再 `sed` 转义（模板展开发生在 sed 之前）。
- **审计要点**：① 不可信输入只进 `env:`，shell 用 `jq --arg`；② `if:` 条件在该 event 上是否引用了恒为 null 的字段导致永真；③ Autofix/AI 评审通过 ≠ 免检。
- **自测**：打开任意 `issues:`/`pull_request_target:` 工作流，标出 `${{ }}` 是否落入 shell 字面量。
- **链接**：https://www.wiz.io/blog/red-agent-snowflake-copilot-cicd-bug

### 2026-09-19 · 安全决策禁止信任客户端 Host / 任意 Bearer

- **危险特征**：本机或 MCP 控制面用 `Host`、`X-Forwarded-*`、任意 `Bearer` 当「已认证」；沙箱挡文件不挡 loopback。
- **审计要点**：① 信任根必须是对端地址、进程身份、签发过的 token 或 Unix socket 权限；② agent 工具可达控制面本身 = 提权面（对照 CVE-2026-82533 / LiteLLM 59822 / Ray UA）。
- **自测**：画出「agent/浏览器 → 控制面 API」可达图，标出鉴权材料是否客户端可控。
- **链接**：Python 时效 2026-09-19；OX CVE-2026-82533

## 十一、AI 辅助审计（可迁移纪律）

> 详细案例与战报拆解见 [`综合分册_AI漏洞挖掘与态势.md`](综合分册_AI漏洞挖掘与态势.md) 第一节与**第五节**。  
> 本节只保留「开工就能勾选」的纪律；周更新纪律以时效条目或下方清单追加。

### 11-1 推荐工作流

1. **人定攻击面**：先填第二节「项目版」入口/汇聚表，再让模型按表深挖——禁止甩整个仓库问「有没有洞」。
2. **SAST/CodeQL 粗筛 → LLM 精判**：规则能写清的交给静态工具；鉴权、净化充分性、IDOR 等模糊判断交给模型，并要求给出文件:行号。
3. **任务拆解文件化**：把「是否鉴权 → 是否净化 → 是否可达 sink → 失败路径是否中止」写成 checklist 或 YAML，逐项喂模型，便于改提示词与复核。
4. **验证门禁**：模型输出默认视为假设；须升到 B 级（sink 可达证据）或 A 级才写入报告。优先沙箱/隔离环境验证。
5. **双角色复核**：高影响结论换提示词角色（攻击者 vs 防御者）或第二模型交叉问一次「为什么不是误报」。
6. **业务逻辑单独会话**：状态机、工单流、支付/权限变更用「时序推演」提示，与危险函数扫描分卷进行。

### 11-2 提示词骨架（可复制改写）

```text
你在做授权代码审计。只分析我给出的文件/片段。
已知攻击面表：（入口 → 可疑 sink）
请按步骤输出：
1) 数据能否从入口到达 sink（调用链，文件:行号）
2) 中间是否有鉴权/净化；失败时是否 return/抛错（防 fail-open）
3) 利用前提（认证与否、配置开关）
4) 最小验证思路（不含完整生产 exploit）
5) 若信息不足，列出还需要我提供的文件，禁止臆造
每条结论必须可被第三节「假设-验证」纪律检查。
```

### 11-3 自测锚点

- [ ] 能说明「为何不整库一问到底」以及如何用攻击面表约束模型
- [ ] 能把一次 CodeQL/Semgrep 告警改写成 taskflow 式逐步研判
- [ ] 能指出至少一种「无沙箱验证」时必须标注的证据等级

### 时效追加

#### 2026-08-09 · 自 NOVA / PRWeaver / GraphAgent 回链

- [ ] **独立验证角色**：发现 Agent 与验证 Agent 分离；验证只认沙箱/干净环境复现。
- [ ] **多模型发现、单标准验收**：发现可集成，入库标准统一（文件:行号 + 证据等级）。
- [ ] **跨 PR / 跨提交追不变量**：鉴权、支付、密钥路径变更不得只审单 diff。
- [ ] **先图/表后模型**：用攻击面表或调用子图收敛上下文，禁止整仓一问到底。
- [ ] **良性叙事提权怀疑**：标注为重构/性能/依赖升级的变更，对安全敏感模块加检。

#### 2026-08-12 · 自 IronCurtain / HTTP Terminator 回链

- [ ] **Journal 外置状态**：长审计用 append-only 日志/文件保存假说与证据；每步新会话，禁止主控吞整仓。
- [ ] **分层 harness**：单函数 fuzz → 多组件 → 全系统/VM，按需升层；无执行证据不升 A 级。
- [ ] **发现与利用拆流**：挖洞工作流止于可达/异常证明；完整利用确认另开人门禁会话。
- [ ] **人在环 cascade**：高价值发现后显式追问「邻近分支/同类解析器」，避免单点收工。

#### 2026-08-12 · 自 FLAWED（AI 补丁）回链

- [ ] **修洞人审强制**：AI 补丁默认不入「已修复」；须回归 + 根因级证据。
- [ ] **拒收 PoC 特化补丁**：仅转义/拦截演示字符串、未动 sink 的改动标失败。
- [ ] **发现与修复分会话**：修复会话禁止静默对照官方 commit 冒充自研成功率。

#### 2026-08-15 · 自 HTTP Terminator 升格回链

- [ ] **专长编码**：只把你已会的审计步骤编成阶段；禁止用通用「找洞」提示词代替攻击面表。
- [ ] **确定性验收**：成功/失败由不可被模型改写的代码或测试锁死；提示词不能当真值。
- [ ] **成立才 cascade**：只对已验证假说追邻近解析器/配置/分支，避免再扫一遍空文档。
- [ ] **分步换干净上下文**：步骤间只传证据与脚本，防止上一步幻觉污染下一步。

#### 2026-08-18 · 自 Wiz Red Agent / Autofix 回链

- [ ] **CI 与应用代码同等门禁**：Autofix/Agent PR 必须过与人码相同的注入规则；「AI 安全评审通过」不能替代。
- [ ] **不可信上下文禁止进 `run:`**：只允许 `env:` + 结构化参数（`jq --arg`）；发现 `${{ github.event.* }}` 进 shell 即 P0。
- [ ] **执行失败当信号**：验证 Agent 要读 stderr/语法错误再改假说，第一次失败不直接标不可达。
- [ ] **图上路径默认候选**：source-to-sink 边若含 INFERRED/AMBIGUOUS，结论不得标 CONFIRMED（对照 offensive-claude v1.9 provenance 门，仅纪律不装库）。
- [ ] **修洞必轮换密钥**：CI 里流出的 token 按已泄露处理，寿命按「数日可被扫」设计。

#### 2026-08-29 · 自 BugHunter「已披露报告接地」回链

- [ ] **hunt 技能用核实过的绕过力学**：禁止只喂 CVE 标题；摘要须对照原文（有无过滤绕过、长度限制、重定向）。
- [ ] **短字段单独开卷**：SSTI/注入探测在长度受限输入上另列最小探测串，不要假设能贴长 polyglot。
- [ ] **平行 Agent 只补缺口轴**：先列出分册已有漏测轴，再让模型对照已披露报告找「我们没写的力学」，禁止整份 skill 入库。

#### 2026-09-19 · 自 AISLE×curl / Harness 自逃逸回链

- [ ] **冷门分支优先**：多 TLS 后端、连接复用、Cookie/PSL、汇编特化路径，不要只扫 strcpy。
- [ ] **AI 计数 ≠ CVE 计数**：只把上游接受或沙箱复现的写入分册。
- [ ] **沙箱必须覆盖 loopback**：挡文件不挡网络等于留门；控制面禁止 Host 当真值。
- [ ] **助手配置当攻击面**：`.cursorrules` / `CLAUDE.md` / `AGENTS.md` 扫零宽字符，不能只审 `.py/.js`。
