# 每周更新 SOP（先进性维持）

> 节奏：每周一（建议 09:00）执行一次，覆盖过去 7 天。  
> 目标：双库内容不腐、可学习可复习；**知识只写进分册**（审计无单独增量池）。  
> 写法：[`文档体例约定.md`](文档体例约定.md)；提示词：[`周更提示词.md`](周更提示词.md)；  
> **关注源**：[`周更重点关注源.md`](周更重点关注源.md)（专家 / 博客 / 厂商 / 论坛，须主动扫）。

## 一、本周要产出什么

| # | 产物 | 路径 |
| --- | --- | --- |
| 1 | 红队每周渗透情报 | `红队渗透知识库/12_每周情报/YYYY-MM-DD_每周渗透情报.md` |

## 二、情报搜集清单（最低覆盖）

> **范围必须大**：官方目录只是地板；P0/P1 专家博客、厂商实验室、论坛线索见关注源清单，缺扫视为未完成周更。

### A. 可武器化漏洞（优先）

- CISA KEV 本周新增
- 边界设备 / 邮件 / 协作套件（Exchange、SharePoint、VPN、网关）
- 国内 OA/协作/安全产品 N-day
- 云控制面与 AI Agent 平台（未授权、越权、代码执行）

### B. 代码审计模式

- 新框架/组件绕过手法（上传、鉴权、反序列化、表达式）
- 补丁 diff 中可复用的失败模式（fail-open、缺 return、校验不全）
- 语言/组件级危险特征，直接进对应分册时效条目

### C. 工具与方法论

- 新工具 / 重大版本 / 替代品
- 高质量博客、演讲、报告中的「可复述一句话精华」
- **必须点名来源**：哪家实验室 / 哪位作者 / 哪个论坛帖（公开 URL）

### D. 自学向（含靶场）

- 新靶场、课程、公开 writeup 中可沉淀的通用技巧

### E. AI 代码审计案例（每周硬性优先）

对公开的 **AI 挖洞 / AI 代码审计 / LLM triage / 多智能体审计** 案例做精析，禁止只写「某某用 AI 挖了很多洞」。每条精析至少抽出：

| 字段 | 说明 |
| --- | --- |
| 场景与目标代码 | 语言/组件/仓库规模（公开描述即可） |
| 管线与分工 | 单模型 / 双模型 / 多 Agent；各角色职责 |
| 提示词与任务拆解 | 可复述的步骤、YAML/taskflow、约束条件（勿抄隐私数据） |
| 工具与上下文 | CodeQL/SAST/MCP/沙箱/调试器等如何接入 |
| 验证闭环 | 如何压误报：沙箱执行、POC、人工门禁 |
| 成果与局限 | 真洞类型、失败案例、不适用场景 |
| **可迁移纪律** | 写成 1～3 条「下次我们用 AI 审计时照做」的 Checklist |

落点：

1. 周报第 4 节「AI 攻防与 AI 审计案例」写摘要 + 链接；
2. 细节写入 `代码审计知识库/综合分册_AI漏洞挖掘与态势.md`「五、AI 审计案例提炼」；
3. 跨语言可复用纪律 → `通用审计方法论.md`「AI 辅助审计」或时效条目。

### F. CTF 奇技淫巧（每周硬性）

对近 7 天放出的 **官方/战队/个人高质量 WP** 做技巧提炼，禁止只列「某杯出了某题」。每条至少抽出：

| 字段 | 说明 |
| --- | --- |
| 技巧一句话 | 可复述的「奇技」本身（绕过点/原语/语言 quirk） |
| 适用面 | Web / Pwn / 反序列化 / 协议 / 内核… |
| 迁移价值 | 审计危险特征？红队打点条件？仅赛题玩具？ |
| 识别/自测 | 源码或流量上怎么认出；一句验证思路 |
| 落点建议 | 写入哪本分册时效条目 / 仅周报观察 |

落点：

1. 周报第 3 节方法论或独立「CTF 奇技」小节写摘要 + 链接；
2. 有代码层可复用模式 → 对应语言分册「时效条目」（或综合分册「CTF 拾遗」）；
3. 纯实战打点向 → 红队相关分册或 `09`（够高频才升格）；
4. 本周无达标技巧 → 周报注明「无达标 CTF 技巧」及已扫赛事/关键词。

红线补充：不写可直接打穿生产的完整 exploit 载荷；赛题非预期解若依赖出题人后门，标注「赛题特化、迁移有限」。

## 三、执行步骤（约 90–120 分钟）

1. **拉仓库最新**，确认上周「入库动作」勾选情况。
2. **打开关注源清单**，按 P0 → P1 勾选扫描；检索词见该文件。
3. **检索**：A–J 全覆盖；优先厂商公告 / NVD / KEV / 实验室博客 / 专家深文 / **新放出 CTF WP** / **免杀与 EDR 对抗文** / **钓鱼与身份攻击文** / **边界设备 PSIRT** / **同类 skill 仓库**；论坛只作线索，回原文核实。
4. **写红队周报**：套用 `12_每周情报/README.md` 模板；每条给「建议动作」；附「本周已扫源」勾选摘要。
5. **写审计分册**：有代码层模式 → 分册「时效条目」；更新页眉日期与 `INDEX.md`。
6. **AI 案例精析**：本周若有合格案例 → 综合分册第五节 +（如有）方法论纪律；若无公开案例，周报注明「本周无达标案例」及已扫关键词（不得空过不提）。
7. **CTF 奇技提炼**：本周若有可迁移技巧 → 周报 + 分册时效（或综合「CTF 拾遗」）；若无，周报注明「无达标 CTF 技巧」及已扫范围。
8. **免杀 / EDR 提炼**：达标手法 → 周报 3.6 + `06-02` 时效；无则注明已扫范围。
9. **钓鱼 / 初始访问提炼**：达标手法 → 周报 3.7 + `03-01` 时效；无则注明已扫范围。
10. **边界设备提炼**：达标条目 → 周报 3.8 + `09-03`（及必要时 `03-02`）；无则注明已扫范围。
11. **同类 skill 库**：达标变化 → 周报 3.9；有缺口则改写分册或标观察；引入 overlay 前走 skill 审查。
12. **红队回链**：打点向 → `09_漏洞库`（边界优先 09-03）；命令/工具 → `10_工具速查`。
13. **勾路线图**：薄分册加厚或 AI/免杀/钓鱼/边界/skill 路由能力条目进度。
14. **提交推送**（按仓库约定脱敏后；若改了 `.agents/skills/` 须先跑 `维护/review-kbs-skills.ps1`）。

## 四、入库红线

- 不写真实目标、IP、域名、凭证、内部组织名。
- 不写可直接复制打穿生产的完整 exploit；写原理、条件、识别特征、防御启示。
- 单一来源未经厂商证实 → 标注「待核实」。
- 情报流水账 ≠ 知识：周报里标「写入分册」的条目须在当次或下周完成；仅「观察」的可不落分册。
- 周报「个人沉淀」含真实环境信息时：先写入本地 `个人笔记/`（gitignore），脱敏后再入库。推送前见 [`隐私与脱敏排查清单.md`](隐私与脱敏排查清单.md)。
- AI 案例精析禁止粘贴可能含客户代码/密钥的原文片段；只留模式与步骤。
- 免杀条目禁止完整生产级 loader/shellcode；只写检测层、原理、适用条件与本地验证思路。
- 钓鱼条目禁止完整 PhaaS 配置/生产诱饵包；只写路径类型、原理、适用条件与本地验证思路。
- 边界条目禁止完整生产级 exploit；只写产品族、识别特征、条件与建议动作。
- 同类 skill 库条目禁止把第三方 SKILL.md 原文入库；只写变化、缺口与审查结论。

## 六、自动化建议

可用 Cursor Automation / 计划任务在每周一触发 Agent，提示词见 `维护/周更提示词.md`（skill：`kbs-weekly-update`）。  
人工仍负责：审核、脱敏、是否写入分册的决策、自学自评、关注源清单增删、第三方 overlay 是否安装。

## 七、归档

- 红队：超过 12 期的周报移入 `12_每周情报/archive/`
- 审计：只维护分册；过时时效条目可标「档案」或删并在周报记录
