# 每周更新 SOP（先进性维持）

> 节奏：每周一（建议 09:00）执行一次，覆盖过去 7 天。  
> 目标：双库内容不腐、可学习可复习；**知识只写进分册**（审计无单独增量池）。  
> 写法：[`文档体例约定.md`](文档体例约定.md)；提示词：[`周更提示词.md`](周更提示词.md)。

## 一、本周要产出什么

| # | 产物 | 路径 |
| --- | --- | --- |
| 1 | 红队每周渗透情报 | `红队渗透知识库/12_每周情报/YYYY-MM-DD_每周渗透情报.md` |
| 2 | 审计模式（有则写） | **直接**写入对应分册「时效条目」+ 必要时 `INDEX.md` |
| 3 | 红队回链（有长期价值才做） | `09_漏洞库` / `10_工具速查` / 相关作战分册 |
| 4 | 路线图勾选 | `维护/内容缺口与补充路线图.md` |

说明：红队周报仍保留，用于「本周发生了什么」的流水与建议动作；审计侧不再另建原料目录，模式级知识一次写进分册。

## 二、情报搜集清单（最低覆盖）

### A. 可武器化漏洞（优先）

- CISA KEV 本周新增
- 边界设备 / 邮件 / 协作套件（Exchange、SharePoint、VPN、网关）
- 国内 OA/协作/安全产品 N-day
- 云控制面与 AI Agent 平台（未授权、越权、代码执行）

### B. 代码审计模式

- 新框架/组件绕过手法（上传、鉴权、反序列化、表达式）
- 补丁 diff 中可复用的失败模式（fail-open、缺 return、校验不全）
- AI 挖洞工具与方法论突破

### C. 工具与方法论

- 新工具 / 重大版本 / 替代品
- 高质量博客、演讲、报告中的「可复述一句话精华」

### D. 自学向

- 新靶场、课程、公开 writeup 中可沉淀的通用技巧

## 三、执行步骤（约 60–90 分钟）

1. **拉仓库最新**，确认上周「入库动作」勾选情况。
2. **检索**：按上表 A–D 搜过去 7 天；优先厂商公告 / NVD / KEV / 可信研究博客。
3. **写红队周报**：套用 `12_每周情报/README.md` 模板；每条给「建议动作」。
4. **写审计分册**：有代码层模式时，直接追加到对应语言分册 / 通用方法论 / 综合分册的「时效条目」（`### YYYY-MM-DD · 标题`）；更新分册页眉日期与 `INDEX.md`。
5. **红队回链**：
   - 打点向 → `09_漏洞库`
   - 命令/工具 → `10_工具速查`
6. **勾路线图**：本周若补了薄分册内容，在路线图标进度。
7. **提交推送**（按仓库约定脱敏后）。

## 四、入库红线

- 不写真实目标、IP、域名、凭证、内部组织名。
- 不写可直接复制打穿生产的完整 exploit；写原理、条件、识别特征、防御启示。
- 单一来源未经厂商证实 → 标注「待核实」。
- 情报流水账 ≠ 知识：周报里标「写入分册」的条目须在当次或下周完成；仅「观察」的可不落分册。
- 周报「个人沉淀」含真实环境信息时：先写入本地 `个人笔记/`（gitignore），脱敏后再入库。推送前见 [`隐私与脱敏排查清单.md`](隐私与脱敏排查清单.md)。

## 五、质量门槛（每期至少满足）

- [ ] 至少 3 条「新漏洞/新利用」，含建议动作
- [ ] 至少 1 条方法论或工具动态
- [ ] 至少 1 条写入分册（审计时效条目或红队 09/10）或明确「观察」理由
- [ ] 个人沉淀区留空位（供手工填写）

## 六、自动化建议

可用 Cursor Automation / 计划任务在每周一触发 Agent，提示词见 `维护/周更提示词.md`。  
人工仍负责：审核、脱敏、是否写入分册的决策、自学自评。

## 七、归档

- 红队：超过 12 期的周报移入 `12_每周情报/archive/`
- 审计：只维护分册；过时时效条目可标「档案」或删并在周报记录
