# 文档体例约定

> 两库分册共用。新写或大改分册时按本约定对齐，避免「有的有自测、有的像随笔」。

## 一、红队分册（`红队渗透知识库/NN_*/`）

推荐结构（可按主题裁剪，但文末锚点必留）：

```markdown
# 标题

> 一句话定位；可选：回链相关分册 / 审计库

## 1. 原理 / 知识点
## 2. 工具与命令（可执行、已脱敏）
## 3. 使用场景 / 决策表
## …（专题节）
## 自测锚点
- [ ] 至少 3 条可勾选、可独立验证的能力陈述
```

- 编号目录 `00_`–`12_` 表示作战阶段，不要随意插入打乱序号。
- 文件名：`01-主题.md`；交叉引用用相对路径或「分区号-文号」（如 `02-01`）。
- 漏洞速查 / 工具速查类可以表格为主，仍须保留「使用纪律 + 自测锚点」。

## 二、审计分册（`代码审计知识库/*_代码审计.md` 等）

推荐结构：

```markdown
# XX 代码审计分册

> 适用场景；更新日期

## 1…N 漏洞模式表（危险特征 | 审计要点 | 验证思路）
## 审计 Checklist
## 工具
## 时效条目（周更直接写入）
### YYYY-MM-DD · 短标题
- 危险特征 / 利用条件 / 审计要点 / 自测锚点（可选）
## 参考资料
```

- `通用审计方法论.md`、`综合分册_*.md` 可按章叙述，但仍建议有 Checklist 或「下期跟踪」。
- `INDEX.md` 只放高频速查；新模式先写分册「时效条目」，够高频再进 INDEX。
- **无增量池**：周更审计内容一次写入分册，不另存原料文件。

## 三-附、AI 审计案例精析体例

```markdown
### YYYY-MM-DD · 短标题（来源：实验室/作者）

- **场景**：语言/组件/公开描述的目标类型
- **管线与分工**：单模型 | 双模型 | Agent 角色（Recon/Analysis/Verify…）
- **提示词 / 任务拆解**：可复述步骤或 taskflow 结构（无客户代码）
- **工具与上下文**：SAST/CodeQL/MCP/沙箱/调试器如何接
- **验证闭环**：如何确认真洞、压误报
- **成果与局限**：洞类型；失败/不适用处
- **可迁移纪律**：
  - [ ] 下次 AI 审计时照做的 Checklist 项 1
  - [ ] 项 2
- **链接**：公开 URL
```

禁止：只有「AI 发现 N 个 CVE」而无分工/验证/可迁移纪律。

## 三-附-2、CTF 奇技提炼体例

```markdown
### YYYY-MM-DD · 短标题（来源：赛事/战队 WP）

- **技巧**：一句话可复述的奇技（绕过点 / 原语 / 语言 quirk）
- **适用面**：Web | Pwn | 反序列化 | 协议 | 内核 | …
- **迁移价值**：审计危险特征 / 红队打点条件 / 仅赛题玩具（三选一写清）
- **识别与自测**：源码或流量上怎么认出；一句验证思路
- **局限**：非预期解、强依赖出题环境等须标注「迁移有限」
- **链接**：公开 WP URL
```

禁止：只贴题名与 flag 思路而无迁移判断；禁止完整生产级 exploit 载荷。

## 三-附-3、免杀 / EDR 时效体例

```markdown
### YYYY-MM-DD · 短标题（来源：实验室/作者）

- **检测层**：静态 | AMSI | 内存 | 行为 | 流量
- **手法**：一句话可复述的对抗点
- **适用条件**：Defender-only / 企业 EDR / 沙箱等
- **本地自测**：授权 VM 如何验证；如何判断死因
- **局限**：公开工具特征已老化等
- **链接**：公开 URL
```

禁止：完整 loader/shellcode、一键免杀包；营销「免杀率」数字。

## 三-附-4、钓鱼 / 初始访问时效体例

```markdown
### YYYY-MM-DD · 短标题（来源：实验室/作者）

- **路径类型**：静态登录页 | AiTM | Device Code | Consent | 附件执行 | Quishing | 水坑
- **手法**：一句话可复述的投递或身份窃取点
- **适用条件**：IdP 策略 / 有无 FIDO2 / 网关类型等
- **本地自测**：授权租户或实验室如何验证；失败点如何判断
- **局限**：PhaaS 特征老化、仅特定租户等
- **链接**：公开 URL
```

禁止：完整 PhaaS 面板配置、生产级诱饵包、可直接滥用的恶意应用注册操作清单。

## 三-附-5、边界设备时效体例

```markdown
### YYYY-MM-DD · 短标题（来源：厂商/实验室）

- **产品族**：VPN | 防火墙 | ADC | 堡垒机 | 邮件网关 | …
- **漏洞/方向**：CVE-… 或一句话
- **识别特征**：标题 / 路径 / 证书 / 端口
- **利用条件**：预认证 | 低权 | 仅管理面暴露
- **建议动作**：写入正式表 / 观察 / 忽略
- **链接**：公开公告 URL
```

禁止：完整生产级 exploit、一键打穿脚本；单一自媒体「在野」须标待核实。

## 三-附-6、同类 Skill 库时效体例

```markdown
### YYYY-MM-DD · 短标题（来源：仓库）

- **仓库**：org/name
- **变化**：新 skill / 新攻击面 / 工作流（一句话）
- **KBS 缺口**：已有 / 应加厚分册 / 仅观察
- **审查**：拒绝 | 有条件本机 overlay | 通过（仍不入库原文）
- **建议动作**：改写分册对照项 / 观察 / 忽略
- **链接**：GitHub URL
```

禁止：把第三方 `SKILL.md`、`scripts/`、完整利用链拷进本仓库。

## 四、文风与红线

- 可执行优先：能搜、能测、能勾选；少空泛形容词。
- 周更来源要宽：专家博客、厂商实验室、论坛回原文、**CTF WP**、**钓鱼/身份攻击战报**、**边界 PSIRT**、**同类 AI 攻防 skill 仓库**，见 `周更重点关注源.md`。
- 不写真实目标/凭证；不写完整生产级 exploit 载荷；不写完整 PhaaS 套件。
- 待核实来源显式标注；过时条目改「档案」或删除并在周报记录。

## 五、双库交叉引用示例

- 红队上传绕过节 → `代码审计知识库/PHP_代码审计.md`「文件上传」
- 审计反序列化节 → `红队渗透知识库/02_Web渗透` / `03_初始访问/04-内存马专项.md`
- 新 KEV 洞 → 红队 `09_漏洞库` + 审计对应语言「时效条目」（若有代码层模式）
