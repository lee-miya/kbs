# 周更 Agent 提示词模板

> 复制到每周一的 Cursor Agent / Automation 中使用。日期按当天替换。

```text
你在 KBS（攻防专业知识库）仓库中执行「每周更新」。

范围：过去 7 天（含今天）的公开安全情报与方法论。
只收录公共知识；禁止写入真实目标、IP、域名、凭证、内部组织名；
禁止写入可直接复用打穿生产的完整 exploit 载荷（写原理、条件、识别特征、建议动作即可）。

【检索范围必须大——强制】
1. 打开并遵守 `维护/周更重点关注源.md`：
   - P0 全部通扫（官方目录、补丁日、云/边界厂商、实验室、国内头部）
   - P0「AI 代码审计专扫」硬性执行
   - P1「CTF 奇技淫巧专扫」硬性执行（可迁移手法，非题解流水账）
   - P1「免杀/EDR 对抗专扫」硬性执行（检测层+手法+自测；禁止完整生产载荷）
   - P1「钓鱼/初始访问专扫」硬性执行（路径类型+手法+自测；禁止完整 PhaaS 套件）
   - P1「边界设备专扫」硬性执行（产品族+指纹+CVE/方向+建议动作；禁止完整 exploit）
   - P1「同类 AI 攻防 Skill 库」硬性执行（新攻击面/工作流/KBS 缺口/审查结论；禁止第三方 SKILL.md 入库）
   - P1 至少精读 2 篇国际 + 2 篇国内（专家博客/实验室/论坛回原文）
   - 不得只依赖 KEV/NVD/新闻聚合站标题党
2. 周报中用简短勾选或列表标明「本周已扫源」档位。

【AI 代码审计案例——强制优先】
对公开的 AI 挖洞 / AI 代码审计 / LLM triage / 多智能体审计案例做精析，
禁止只写「某某用 AI 挖了很多洞」。每条须提取：
- 场景与目标代码类型
- 管线与分工（单/双模型、多 Agent 角色）
- 提示词或任务拆解结构（可复述步骤；勿抄隐私代码）
- 工具与上下文接入（CodeQL/SAST/MCP/沙箱等）
- 验证闭环（如何压误报）
- 成果类型与局限
- 可迁移纪律（1～3 条 Checklist：下次我们用 AI 审计时照做）
落点：周报第 4 节摘要 + `综合分册_AI漏洞挖掘与态势.md`「五、AI 审计案例提炼」；
跨语言纪律写入 `通用审计方法论.md`「AI 辅助审计」或时效条目。
若本周无达标公开案例：在周报写明「无达标案例」及已搜关键词/已扫源，不得省略本节。

【CTF 奇技淫巧——强制】
扫描近 7 天新放出的官方/战队/高赞 WP（CTFtime、看雪/先知 WP、各大杯官方 Writeup）。
每条可入库技巧须提取：
- 技巧一句话（绕过/原语/语言 quirk）
- 适用面与迁移价值（审计危险特征 / 红队条件 / 仅赛题玩具）
- 识别与自测思路
- 落点建议（哪本分册时效 / 仅观察）
禁止只列题名；赛题特化非预期解标注「迁移有限」。
落点：周报方法论或「CTF 奇技」小节 +（有代码层则）对应分册时效或综合分册「CTF 拾遗」。
若本周无达标技巧：写明「无达标 CTF 技巧」及已扫赛事/关键词，不得空过。

【免杀 / EDR 对抗——强制】
扫描近 7 天公开的 EDR/AMSI/sleep/syscall/LOLBins/loader 研究与厂商检测通告。
每条可入库手法须提取：
- 检测层（静态/AMSI/内存/行为/流量）
- 手法一句话与适用条件
- 本地自测/判死因思路
- 落点（06-02 时效 / 10 / 仅观察）
禁止完整生产级 loader/shellcode。
落点：周报「3.6 免杀与 EDR」+ `06_C2与后渗透/02-免杀与载荷对抗.md` 时效条目。
若本周无达标：写明「无达标免杀条目」及已扫关键词/源，不得空过。

【钓鱼 / 初始访问——强制】
扫描近 7 天公开的 AiTM / Device Code / Consent / Quishing / HTML Smuggling / PhaaS 研究与战报。
每条可入库手法须提取：
- 路径类型（静态页/AiTM/Device Code/Consent/附件/Quishing…）
- 手法一句话与适用条件（含对 FIDO2/Passkey 是否仍有效）
- 本地自测/失败点判断思路
- 落点（03-01 时效 / 10 / 06-02 若涉载荷 / 仅观察）
禁止完整 PhaaS 面板配置与生产级诱饵包。
落点：周报「3.7 钓鱼与初始访问」+ `03_初始访问/01-钓鱼与社会工程.md` 时效条目。
若本周无达标：写明「无达标钓鱼条目」及已扫关键词/源，不得空过。

【边界设备——强制】
扫描近 7 天公开的 VPN / 防火墙 / ADC / 堡垒机 / 邮件网关 / 零信任控制台通告与在野利用（厂商 PSIRT + KEV + 国内边界产品）。
每条可入库条目须提取：
- 产品族与漏洞/方向（CVE 或一句话）
- 识别特征（标题/路径/证书）
- 利用条件（预认证/低权/管理面暴露）
- 建议动作（写入 09-03 / 观察 / 忽略）
禁止完整生产级 exploit。
落点：周报「3.8 边界设备」+ `09_漏洞库/03-边界设备漏洞速查.md`；打法纪律变化回链 `03-02`。
若本周无达标：写明「无达标边界条目」及已扫厂商/关键词，不得空过。

【同类 AI 攻防 Skill 库——强制】
扫描关注源 P1 名单（Claude-Red、Claude-BugHunter、Claude-OSINT、offensive-claude 等）近 7 天 README/Release/commits。
每条可入库变化须提取：
- 仓库与链接
- 变化一句话（新 skill / 新攻击面 / 工作流）
- KBS 缺口（已有 / 应加厚哪本 / 仅观察）
- 安全审查结论（拒绝 / 有条件本机 / 通过）；拟 overlay 必须先过 `维护/Skill安全审查清单.md`
- 建议动作（改写分册 / 本机 overlay / 观察 / 忽略）
禁止把第三方 SKILL.md 或攻击 scripts 写入本仓库。
落点：周报「3.9 同类 Skill 库」。
若本周无变化：写明「无达标 skill 库变化」及已扫仓库，不得空过。

请按 `维护/每周更新SOP.md` 执行，并产出：

1. `红队渗透知识库/12_每周情报/YYYY-MM-DD_每周渗透情报.md`
   - 结构必须符合该目录 README 模板（含「已扫源」、AI 案例节、CTF 奇技、**免杀 3.6**、**钓鱼 3.7**、**边界 3.8**、**同类 skill 3.9**）
   - 每条漏洞给「建议动作」：写入 09 / 09-03 / 观察 / 忽略

2. 审计侧：有代码层模式时，**直接**追加到对应分册「时效条目」
   （PHP/Java/Python/Node/Go/C++/通用方法论/综合分册），格式：
   `### YYYY-MM-DD · 短标题` + 危险特征 / 利用条件 / 审计要点
   - 不要创建或使用「增量池」目录
   - 更新该分册页眉日期与 `代码审计知识库/INDEX.md` 最近更新日期

3. AI 案例精析写入综合分册第五节（有则写）；可复用纪律回链方法论

4. CTF 可迁移奇技写入对应分册时效或综合「CTF 拾遗」（有则写）

5. 免杀手法写入 `06-02` 时效（有则写）；工具变化回链 `10`

6. 钓鱼手法写入 `03-01` 时效（有则写）；工具变化回链 `10`

7. 边界设备写入 `09-03`（有则写）；打法纪律回链 `03-02`

8. 同类 skill 库写入周报 3.9；有缺口则改写分册（禁止粘贴第三方 SKILL.md）

9. 红队回链（有长期价值）：
   - 打点向 → `红队渗透知识库/09_漏洞库/`（边界优先 09-03）
   - 工具命令 → `10_工具速查`

10. 更新 `维护/内容缺口与补充路线图.md`「本周已执行」勾选
11. 若本周有余力：按路线图 P0 给一个分册加厚一小段，不要大改无关文件
12. 发现优质新源：追加到 `维护/周更重点关注源.md` 对应档位
13. 若改动 `.cursor/skills/`：运行 `维护/review-kbs-skills.ps1` 通过后再提交

完成后：按 `维护/文档体例约定.md` 检查格式；git status 自检无敏感信息，按仓库约定提交并推送。
```

## 人工复核清单

- [ ] 来源可信；「待核实」已标注；关注源 P0/P1 已覆盖而非只扫聚合站
- [ ] 无敏感信息
- [ ] 建议动作合理（不是每条都强行入库）
- [ ] 审计新模式已在分册「时效条目」中可检索（无遗留增量池文件）
- [ ] AI 案例有「可迁移纪律」，不是新闻摘要
- [ ] CTF 条目有「迁移价值」判断，不是题解目录
- [ ] 免杀条目有「检测层」且无完整生产载荷
- [ ] 钓鱼条目有「路径类型」且无完整 PhaaS/诱饵包
- [ ] 边界条目有「产品族 + 识别特征」且无完整 exploit
- [ ] 同类 skill 库 3.9 已写（或「无达标变化」）；无第三方 SKILL.md 入库
- [ ] 新增/改写分册符合体例（自测锚点或 Checklist + 时效区）
