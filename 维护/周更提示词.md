# 周更 Agent 提示词模板

> 复制到每周一的 Cursor Agent / Automation 中使用。日期按当天替换。

```text
你在 KBS（攻防专业知识库）仓库中执行「每周更新」。

范围：过去 7 天（含今天）的公开安全情报与方法论。
只收录公共知识；禁止写入真实目标、IP、域名、凭证、内部组织名；
禁止写入可直接复用打穿生产的完整 exploit 载荷（写原理、条件、识别特征、建议动作即可）。

【检索范围必须大——强制】
1. 打开并遵守 `维护/周更重点关注源.md`：
   - P0 全部通扫（官方目录、补丁日、云/边界厂商、实验室、国内头部）
   - P0「AI 代码审计专扫」硬性执行
   - P1「CTF 奇技淫巧专扫」硬性执行（可迁移手法，非题解流水账）
   - P1「免杀/EDR 对抗专扫」硬性执行（检测层+手法+自测；禁止完整生产载荷）
   - P1 至少精读 2 篇国际 + 2 篇国内（专家博客/实验室/论坛回原文）
   - 不得只依赖 KEV/NVD/新闻聚合站标题党
2. 周报中用简短勾选或列表标明「本周已扫源」档位。

【AI 代码审计案例——强制优先】
对公开的 AI 挖洞 / AI 代码审计 / LLM triage / 多智能体审计案例做精析，
禁止只写「某某用 AI 挖了很多洞」。每条须提取：
- 场景与目标代码类型
- 管线与分工（单/双模型、多 Agent 角色）
- 提示词或任务拆解结构（可复述步骤；勿抄隐私代码）
- 工具与上下文接入（CodeQL/SAST/MCP/沙箱等）
- 验证闭环（如何压误报）
- 成果类型与局限
- 可迁移纪律（1～3 条 Checklist：下次我们用 AI 审计时照做）
落点：周报第 4 节摘要 + `综合分册_AI漏洞挖掘与态势.md`「五、AI 审计案例提炼」；
跨语言纪律写入 `通用审计方法论.md`「AI 辅助审计」或时效条目。
若本周无达标公开案例：在周报写明「无达标案例」及已搜关键词/已扫源，不得省略本节。

【CTF 奇技淫巧——强制】
扫描近 7 天新放出的官方/战队/高赞 WP（CTFtime、看雪/先知 WP、各大杯官方 Writeup）。
每条可入库技巧须提取：
- 技巧一句话（绕过/原语/语言 quirk）
- 适用面与迁移价值（审计危险特征 / 红队条件 / 仅赛题玩具）
- 识别与自测思路
- 落点建议（哪本分册时效 / 仅观察）
禁止只列题名；赛题特化非预期解标注「迁移有限」。
落点：周报方法论或「CTF 奇技」小节 +（有代码层则）对应分册时效或综合分册「CTF 拾遗」。
若本周无达标技巧：写明「无达标 CTF 技巧」及已扫赛事/关键词，不得空过。

【免杀 / EDR 对抗——强制】
扫描近 7 天公开的 EDR/AMSI/sleep/syscall/LOLBins/loader 研究与厂商检测通告。
每条可入库手法须提取：
- 检测层（静态/AMSI/内存/行为/流量）
- 手法一句话与适用条件
- 本地自测/判死因思路
- 落点（06-02 时效 / 10 / 仅观察）
禁止完整生产级 loader/shellcode。
落点：周报「3.6 免杀与 EDR」+ `06_C2与后渗透/02-免杀与载荷对抗.md` 时效条目。
若本周无达标：写明「无达标免杀条目」及已扫关键词/源，不得空过。

请按 `维护/每周更新SOP.md` 执行，并产出：

1. `红队渗透知识库/12_每周情报/YYYY-MM-DD_每周渗透情报.md`
   - 结构必须符合该目录 README 模板（含「已扫源」、AI 案例节、CTF 奇技、**免杀 3.6**）
   - 每条漏洞给「建议动作」：写入 09 漏洞库 / 观察 / 忽略

2. 审计侧：有代码层模式时，**直接**追加到对应分册「时效条目」
   （PHP/Java/Python/Node/Go/C++/通用方法论/综合分册），格式：
   `### YYYY-MM-DD · 短标题` + 危险特征 / 利用条件 / 审计要点
   - 不要创建或使用「增量池」目录
   - 更新该分册页眉日期与 `代码审计知识库/INDEX.md` 最近更新日期

3. AI 案例精析写入综合分册第五节（有则写）；可复用纪律回链方法论

4. CTF 可迁移奇技写入对应分册时效或综合「CTF 拾遗」（有则写）

5. 免杀手法写入 `06-02` 时效（有则写）；工具变化回链 `10`

6. 红队回链（有长期价值）：
   - 打点向 → `红队渗透知识库/09_漏洞库/`
   - 工具命令 → `10_工具速查`

7. 更新 `维护/内容缺口与补充路线图.md`「本周已执行」勾选
8. 若本周有余力：按路线图 P0 给一个分册加厚一小段，不要大改无关文件
9. 发现优质新源：追加到 `维护/周更重点关注源.md` 对应档位

完成后：按 `维护/文档体例约定.md` 检查格式；git status 自检无敏感信息，按仓库约定提交并推送。
```

## 人工复核清单

- [ ] 来源可信；「待核实」已标注；关注源 P0/P1 已覆盖而非只扫聚合站
- [ ] 无敏感信息
- [ ] 建议动作合理（不是每条都强行入库）
- [ ] 审计新模式已在分册「时效条目」中可检索（无遗留增量池文件）
- [ ] AI 案例有「可迁移纪律」，不是新闻摘要
- [ ] CTF 条目有「迁移价值」判断，不是题解目录
- [ ] 免杀条目有「检测层」且无完整生产载荷
- [ ] 新增/改写分册符合体例（自测锚点或 Checklist + 时效区）
